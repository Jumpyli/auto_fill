# Form filler — update history

**Git covers almost none of this.** `git log --follow content/fill.js` shows one commit: `2619e31` "Initial commit" (2026-11-18), which contains every change below. The reasons below come from the development session (source: "Development session, 2026-11-18"). In order, oldest first.

| # | Date | What changed | Why | Source |
|---|---|---|---|---|
| 1 | 2026-11-18 | **Built as a browser extension that reads the page's HTML.** Not a local vision model that screenshots and scrolls the screen | The user proposed a light local vision model. Reading the page's structure gives exact question and option text without scrolling, and is faster and lighter | Development session, 2026-11-18 |
| 2 | 2026-11-18 | **Firefox add-on** (WebExtension, Manifest V2) | The user uses Firefox. MV2 grants host access at install, which content scripts need inside cross-origin iframes (for example a Greenhouse form embedded on a company site). The details live in the shell docs | Development session, 2026-11-18 |
| 3 | 2026-11-18 | **v1 shipped:** text/select/radio/checkbox/file filling, colored outlines, results panel, learning. Leaves already-filled fields alone; always skips agreements and signatures; never submits | User requirement: fill everything but never submit, so the user can review | Development session, 2026-11-18 |
| 4 | 2026-11-18 | **Frames without fields stay silent** (line 503). Before this, they answered `null` | The popup takes the first answer from any frame, so an empty top frame could hide the counts from the iframe holding the form. Fixed before first use | Development session, 2026-11-18 |
| 5 | 2026-11-18 | **Group question text only from a container holding one question** (`onlyThis`, line 62) | First real test on Lockheed Martin (Eightfold, `lockheedmartin.eightfold.ai`): both yes/no questions were labeled "Application Questions", the section title | Development session, 2026-11-18 (Lockheed screenshot) |
| 6 | 2026-11-18 | **"If you answered…" follow-ups are skipped** unless an exact answer was saved (line 289). They can still be learned (`learnable`) | Same Lockheed test: the former-employee ID box matched "previously worked here" and would have received "No" | Development session, 2026-11-18 (Lockheed screenshot) |
| 7 | 2026-11-18 | **Custom dropdowns are filled** (`fillCombo`, lines 198–237). Also covers non-input dropdowns (line 108), and learning reads them (line 466) | The second Lockheed test showed "Custom dropdown. Pick 'No' yourself" for sponsorship and veteran status, although the answers were in the bank | Development session, 2026-11-18 (Lockheed screenshot) |
| 8 | 2026-11-18 | **Read-only custom dropdowns are no longer skipped** (lines 103–105) | Found while testing #7: read-only inputs were dropped before the dropdown check, and sites often make dropdown inputs read-only | Development session, 2026-11-18 |
| 9 | 2026-11-18 | **Learning saves a manual answer under the form's exact wording** when the question matched a broader bank question that already has an answer (`learn()`). That bank answer is never overwritten | Lockheed: "Do you possess the Bachelor's Degree?" (Yes/No) matched the "Degree" answer ("Bachelor's degree in Computer Science…"). The user picked Yes and clicked Save, and got "No new answers to save" | Development session, 2026-11-18 (Lockheed screenshot) |
| 10 | 2026-11-18 | **Yes/No questions with a non-yes/no answer say so** in the panel | Same case: the old note, "doesn't match any choice", didn't say what to do | Development session, 2026-11-18 |
| 11 | 2026-11-18 | **Custom dropdown failures give the reason** ("couldn't open the menu" vs "no option matched, saw: …") and keep the dropdown's HTML for a **Copy debug info** button | On the real Lockheed page, the Visa status and Protected Veteran Status dropdowns failed even though their answers exist. Mock tests had passed, so the real menu structure is needed | Development session, 2026-11-18 (Lockheed screenshot) |
| 12 | 2026-11-18 | Radio items remember their buttons (`item.inputs`). Learning reads the checked one from them instead of a name selector | Simpler, and works for radio buttons without a `name` | Development session, 2026-11-18 |
| 13 | 2026-11-18 | **Agreements and signatures are skipped for every field type** (was: text boxes and single checkboxes only). Signature detection adds "please sign", "sign by", "sign here/below" (`isConsent` in `lib/match.js`) | Lockheed's "Please sign by typing your full legal name" wasn't recognized and would have received the "Full legal name" answer on a fresh form. "I have read and understand and I agree to the above" may be a dropdown or radio question | Development session, 2026-11-18 (Lockheed screenshot) |
| 14 | 2026-11-18 | **A dropdown only reads its own menu.** When it names one (`aria-controls`/`aria-owns`), no other menu counts. Without a named menu, only a listbox that appeared after opening it counts. Each menu is closed (Escape + blur) before the next dropdown. Dropdowns already showing the answer aren't opened. Typed filter text is undone on failure. Debug info records each step (`expanded=…, menu=…`) | Debug info from Lockheed: the Visa status and Veteran Status dropdowns' own menus (`list-39`, `list-78`) never opened, and the add-on read a leftover **Yes/No** menu from another question instead. With a matching answer, it could have clicked an option in the wrong question | Development session, 2026-11-18 (Lockheed debug info) |

## Reversed decisions (don't undo these)

| Original choice | Reversed to | Reason | Don't go back because |
|---|---|---|---|
| v1: custom dropdowns are **not** filled; the panel says "pick it yourself" (chosen for reliability, since sites build these menus differently) | Fill them with `fillCombo` | Lockheed, the user's main target for the next few months, uses custom dropdowns for required questions | Going back makes the main target site half-manual again. If a site's dropdown misbehaves, handle that site rather than removing the feature |
| v1: a fieldset `<legend>` is always trusted as the group's question | Only trusted when the fieldset holds just that one group | Lockheed wraps all questions in one section | Trusting the legend again brings back the "Application Questions" labels, and then wrong learned answers |
| v1: learning never adds an entry when the field matched a bank question that already has an answer | Save the manual answer as a new entry with the form's exact wording | A broader answer ("Degree") blocked learning the specific Yes/No answer | Going back means a manual fix is never remembered, and the same field stays red on every application |
| v1 of custom dropdowns: if the named menu isn't found, use any visible menu on the page | Only the dropdown's own menu (or one that appeared after opening it) | It read, and could have clicked, another question's leftover Yes/No menu on Lockheed's form | Going back risks changing answers to the wrong questions |
| v1: follow-up questions match like any other | Skipped unless there's an exact saved answer | Wrong values in ID fields | Lowering the 0.99 threshold refills unrelated answers into conditional fields |
